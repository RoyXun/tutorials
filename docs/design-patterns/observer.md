# 观察者模式

[观察者模式(Observer Pattern)](https://en.wikipedia.org/wiki/Observer_pattern)是一种**行为型模式**，用于建立对象间一对多的依赖关系，当对象状态改变时，所有依赖它的对象都会收到通知并自动更新。

## 使用场景

观察者模式主要解决以下需求：

- 避免定义对象之间一对多依赖关系时对象强耦合；
- 当主题状态改变时，所有注册的观察者能被通知到并自动更新；
- 一个对象可以通知多个其它对象。

## 结构与实现

观察者模式通常包含以下角色：

- **抽象主题(Subject)**: 它是有状态的对象，维护着一个观察者列表,并定义了添加、删除和通知观察者的方法。
- **具体主题(ConcreteSubject)**：实现抽象主题，维护自身状态，并在状态改变时通知观察者。
- **抽象观察者(Observer)**: 定义响应方法update()。
- **具体观察者(ConcreteObserver)**：实现抽象观察者，维护对具体主题的引用，并在update()中获取主题状态进行处理。

![Observer UML](/images/pattern/observer.png)

观察者模式通过将主题与观察者解耦，实现了对象之间的松耦合。当主题的状态发生变化时，所有依赖于它的观察者都会收到通知并进行相应的更新。

## 优缺点

优点：

- **低耦合**：主题和观察者之间通过抽象接口交互，不依赖具体实现。
- **易扩展**： 可以动态增删观察者，无需修改主题代码。
- **实时更新**：状态变化能及时通知所有依赖对象。

缺点：

- **性能问题**： 观察者数量过多时，通知操作可能变慢。
- **循环依赖**：可能导致循环调用和系统崩溃。
- **缺乏变化详情**：观察者只知道变化发生，不知道主题如何变化。

## 对比发布订阅模式

广义上讲，观察者模式是一种发布订阅模式(publish-subscribe pattern)，但严格来说两者在架构、耦合性和常见用例等方面有很大的不同。

| 特性             | 观察者模式                                     | 发布订阅模式                                           |
| ---------------- | ---------------------------------------------- | ------------------------------------------------------ |
| **耦合**         | 紧耦合——主题通过标准接口持有观察者的直接引用。 | 松耦合——发布者和订阅者互不知晓。                       |
| **通信**         | 直接——主题调用观察者方法。                     | 间接——代理（消息总线或事件管理器）将消息分发给订阅者。 |
| **参与者知晓性** | 主题知道其观察者。                             | 发布者和订阅者互相解耦，互不了解。                     |
| **扩展性**       | 适用于诸如GUI工具等进程内系统。                | 更具扩展性；支持分布式系统和异步通信。                 |
| **同步/异步**    | 通常是同步的，但是可以通过事件队列实现异步。   | 通常是异步的，但是可以是同步的。                       |
| **过滤**         | 有限——观察者接收所有事件并在内部过滤。         | 丰富的过滤——代理可以根据主题、内容或规则进行过滤。     |
| **容错**         | 观察者故障能影响主题。                         | 故障隔离：代理解耦参与者。                             |
| **典型用法**     | GUI框架、MVC架构、本地对象通知。               | 微服务、分布式系统、消息中间件。                       |

## 示例

标准观察者模式：

```js
// 主题 (被观察者)
class Subject {
  constructor() {
    this.observers = [];
  }
  // 直接持有观察者列表
  subscribe(observer) {
    this.observers.push(observer);
  }
  notify() {
    // 直接调用每一个观察者的方法
    this.observers.forEach((o) => o.update());
  }
}
```

引入事件总线的发布订阅：

```js
// 中间层：事件总线
const eventBus = {
  events: {},
  // 订阅
  on(event, callback) {
    if (!this.events[event]) this.events[event] = [];
    this.events[event].push(callback);
  },
  // 发布
  emit(event, data) {
    if (this.events[event]) {
      this.events[event].forEach((cb) => cb(data));
    }
  },
};

// 发布者
eventBus.emit("user.login", { name: "张三" });
// 订阅者 (不知道是谁发布的，只监听事件)
eventBus.on("user.login", (user) => console.log(user.name));
```
